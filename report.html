Page 3: Feature Issue and Backlog

Student Attendance Management

Student Attendance

The Student Attendance feature is created as a parent issue. It defines the requirements for recording, storing, and displaying student attendance. As the umbrella epic, it unites all institutional attendance requirements into clear engineering acceptance criteria.

Main Requirements

  • Record attendance as Present or Absent.
  • Store attendance date, subject/class code, and student details.
  • Allow authorized faculty to mark attendance with credential verification.
  • Display attendance records and compute percentage in real time.
  • Prevent duplicate attendance entries for the same student, subject, and session.

Feature List

The project board contains the following main feature issues:

  1. User Login and Authentication (Issue #2)
  2. Attendance Marking (Issue #3)
  3. Attendance Reports (Issue #4)
  4. Notifications (Issue #5)

Page 5: Notifications Feature

Notifications and Alerts

The Notifications feature is planned as the fourth main product feature. It provides an automated communication loop between faculty marking actions, attendance calculations, and student awareness.

Notification Tasks

  1. Attendance update notification: Sent immediately to students when attendance for a lecture session is recorded.
  2. Low-attendance alert: Automated warning banner and notification triggered when a student's attendance drops below 75%.
  3. Attendance correction notification: Sent when faculty modifies or updates a past session entry.
  4. Notification delivery status: Tracking unread badges, read status, and delivery timestamps.
  5. Notification testing: Unit, integration, and UI acceptance testing of alerts.

Integration

The notification module is integrated with attendance marking and attendance reports so students can receive important updates in real time without polling or manual inquiries.

Page 8: Sprint 1 — User Login and Authentication

Assigned Member: Vamshi (with manukanta)

Sprint Tasks

  1. Design the login page: Create a responsive, intuitive interface for students and faculty.
  2. Implement student and faculty login: Support separate credential paths and roles.
  3. Validate login credentials: Enforce format checks, error messaging, and password security.
  4. Add role-based access: Route faculty to marking and analytics dashboards; route students to personal attendance and alerts.
